# Автоматическое обновление памяток и отработки Неба — 16.11.2026

## Подтверждённые уточнения

Юлия указала, что в картинке Неба оставались старые условия отработок. Действует ранее согласованное правило CRM-053: месяц пропуска или сразу следующий; месяц отработки оплачен месячным абонементом; в неделе пн–вс достаточно двух оплаченных занятий по абонементу, фактических посещений ждать не нужно; отработка дополнительная, третья/четвёртая и далее. Только явно отмеченные пропуски, включая будущие, без повторного использования отработанных/пересчитанных.

Новое прямое требование: изменение правил абонементов должно автоматически менять картинки. Получены отдельная ссылка «Написать нам в MAX», публичные ссылки MAX Неба и Западного; малыши используют канал Неба. Контакт администратора не подменяет канал филиала. Ссылка Арктики пока ожидается; существующее напоминание на 17:05 МСК уточнено только для неё.

## Реализация

- Статические дизайнерские PNG больше не обходят проверку актуальности. Исходные картинки сохранены в истории/репозитории, но ручной скрипт отправляет только актуальный сгенерированный PNG из `memo_images`.
- Срок окна отработки и минимум оплаченных занятий вынесены в общие константы `logic`; те же значения используют допуск на отработку и данные памятки. Старое ограничение «только в текущем месяце» убрано.
- В отпечаток изображения входят текущие/следующие цены, надбавка, срок продления, лимит перерасчётов, семейная скидка сборной, расписание, условия отработок, содержимое JS-шаблона и фона. Условия берутся из действующих данных, дата — Europe/Moscow.
- Перерисовка запускается после изменения настроек/цен/скидок/расписания, перед открытием скриптов, при входе и раз в минуту в видимой CRM. Параллельные запросы объединяются. Изображение с устаревшим отпечатком не принимается сервером и не выдаётся для отправки. Если меняются данные во время отрисовки, выполняется повторное чтение/генерация.
- Условия и суммы рисует canvas поверх фирменного фона с иллюстрациями. Высота подстраивается под текст, длинные строки в тарифах переносятся. Свежий PNG не кешируется на час: `Cache-Control: no-store`, версия в URL предпросмотра. Ранее выбранный черновик с устаревшими правилами дополнительно блокируется при отправке.
- Контакт MAX добавляется в сопроводительный текст отдельной строкой; каналы Неба и Западного — отдельные значения по умолчанию с возможностью изменить в настройках. Явно сохранённые настройки не перезаписываются. Локальный JSON импорта дополнен новыми ссылками; приватные Telegram-приглашения в публичный репозиторий не добавляются.

## Проверки и границы

Пройдены 15 прежних целевых модулей, `test_makeup_policy`, пять тестов `test_memo_refresh`, всего 17 модулей. Проверены смена цены/срока/окна отработки/минимума занятий/расписания/шаблона, инвалидирование старого PNG и отказ принять результат устаревшей генерации. `test_chat_scripts` обновлён под отказ от статического обхода и новые ссылки MAX. Python compileall, JS node --check, git diff --check.

На отдельной синтетической CRM через настоящий HTTP + Chromium подтверждены: автоматическое изменение отпечатка и пикселей после API-сохранения новой цены и срока без ручного запуска рисования; отказ отправить старый черновик; `no-store`; каждый PNG меньше 5 МБ; отсутствие ошибок JS. Пройден полный сценарий текста+PNG в чате, отдельной demo-отправки, импорта/сохранения настроек. Сгенерированные изображения Неба, малышей и сборной просмотрены визуально: текст читается, не обрезан.

Это не изменение рабочих оплат/клиентских данных, не проверка доставки мессенджером и не проверка конкретной производственной карточки. Перерисовку выполняет открытая авторизованная CRM администратора; без такой сессии старый PNG блокируется до генерации свежего. Публикация и публичная проверка фиксируются отдельно после push. Ранее зафиксированный сетевой блокер Telegram/доступ к серверу остаётся.
