Юлия разрешила публикацию описанного ea31dae. Коммит не найден локально/remote, GitHub API /commits/ea31dae вернул HTTP 422 No commit found. Поэтому cherry-pick не заявляется: описанное поведение реализовано самостоятельно поверх актуального main с сохранением текущих изменений.

В карточке, редакторе основных данных и «Клиенты и лиды» отображается исходный erp_status либо «Статус ERP не перенесён». Убран отдельный внутренний этап из интерфейса карточки; редактор сохраняет его скрытым неизменным значением. Единственный фильтр статуса использует ERP; доступен фильтр отсутствующего значения. Внутренние этапы, цепочки задач, признак лид/клиент, оплаты и исходные данные не переписываются. Старые параметры status/erp API интерпретируются по ERP, UI передаёт erp.

Проверены test_people (статусы, фильтры, отсутствующие значения, лиды, поиск, архив), четыре test_client_profile и синтаксис JS/Python. Chromium проверяет список 390/1440, фильтр и отсутствие дублей статуса; существующий тест редактора контактов также прошёл. Общий прогон 89/94 из переданного сообщения не воспроизводился и не объявляется нашим результатом.
