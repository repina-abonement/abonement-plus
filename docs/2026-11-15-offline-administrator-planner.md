# Общий Планер офлайн-администраторов

## Требование

Юлия поручила роль офлайн-администратора Данейкиной и Сафроновой. Все сотрудники роли работают в одном Планере, Варя и руководитель могут видеть его, остальные не имеют доступа. Просмотр Вари реализован без редактирования, чтобы не расширять явно запрошенные полномочия.

## Реализация

Флаг is_offline_admin при базовой роли operator сохраняет обычные права администратора и отображается отдельной должностью. В настройках сотрудников можно выбрать должность; после её изменения прежние сессии закрываются. Общие задачи и серии принадлежат отдельному отключённому служебному владельцу без возможности входа; он не появляется среди сотрудников. Это один набор записей, а не копии персональных задач. Офлайн-администратор по умолчанию открывает общий Планер и создаёт общие задачи; руководитель выбирает общий Планер в списке.

Доступ определяется отдельно от старшинства: роль/руководитель редактируют, один явно выбранный наблюдатель читает. Выбор наблюдателя доступен только руководителю в Планер → Команда. API ограничивает недели/карточки/выбор исполнителя/выполнение/перенос/открытие/отмену/повторы, а общие списки задач используют тот же фильтр видимости. Наблюдатель не видит кнопок изменения; прямые запросы тоже отклоняются.

Однократная настройка по поручению пользователя после инициализации ищет точные отдельные слова фамилий и имя Варя/Варвара среди активных пользователей role=operator. Требуются три уникальных разных аккаунта. При неоднозначности ничего не меняется, руководитель назначает через настройки. При успехе обе роли и наблюдатель записываются атомарно, изменения попадают в аудит; маркер защищает позднейшие ручные изменения от повторного применения. Это механизм назначения, а не доказательство его результата в рабочей БД.

Проверены общий набор у двух редакторов, завершение коллегой, наблюдатель без мутаций, отказ постороннему старшему, приватность общих выборок, повторы, отсутствие переноса личной истории, неоднозначные фамилии, одноразовость настройки.
