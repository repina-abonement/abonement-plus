# Страница оплаты, email и обработка данных — 17 ноября 2026

## Поручения

Подробно и читабельно показать родителю, за что он платит. Позднее Юлия изменила прежнее требование email: если он ранее вводился на этой форме или есть в семье, не просить вводить заново. Дополнительно проверить необходимость согласия на обработку данных

## Реализация

GET публичной непросроченной токен-ссылки возвращает только данные этой оплаты: ребёнок, сохранённые компоненты/даты абонемента, текущие названия групп/филиалы, месяц/срок, тариф, число занятий, исключения, суммы и скидка. Контакты родителей, внутренняя история и ID не показываются. Добавлена проверка принадлежности абонемента ребёнку ссылки. Для старого состава без снимка даты не выдумываются; для неприкреплённой ссылки показаны ребёнок/назначение/сумма

Предзаполнение: сначала receipt_email уже созданного текущего счёта (не меняется), затем последний валидный email успешного создания счёта в этой семье, затем валидные адреса родителей с приоритетом основного. Чужая семья не используется; неверные адреса пропускаются. До создания счёта адрес редактируется, в карточку не записывается. Сервер по-прежнему проверяет любой email перед созданием счёта. Сохранены прежние сумма/orderid/зачисление/защита повторного счёта

Страница без внешних шрифтов/аналитики, no-referrer/no-store, DOM textContent вместо HTML данных. Адаптивная белая карточка, итог оплаты, частичная сумма/остаток, даты чипами, понятное назначение email. Без маркетинговых галочек и ложной записи общего согласия семьи

## Правовая проверка и ограничение

Статья 6 ч. 1 п. 2/5 152-ФЗ допускает необходимую обработку по закону/для исполнения договора без универсального отдельного согласия. Указание адреса и подтверждение оплаты сопровождаются пояснением об электронном чеке и ссылкой на политику. Это не отдельное согласие на рекламу, распространение данных, здоровье или прочие цели. Если для иных целей требуется согласие, его необходимо оформлять отдельно, а не смешивать с этой оплатой
