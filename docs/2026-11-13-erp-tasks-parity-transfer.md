# Задачи как в ERP и отдельный перенос реестра — 13 ноября 2026

## Приоритет пользователя

До адаптации администраторов логика клиентских задач CRM должна воспроизводить ERP. Новые интервалы, переходы и названия не считать улучшением по умолчанию. Главный практический приоритет — быстро и повторяемо перенести все клиентские задачи. Источник: актуальный реестр задач ERP, не журнал событий и не история карточек.

## Изученные источники

На подключённом Google Диске прочитаны «Копия Инструкция по задачам ERP» (последнее изменение 29.08.2022) и «Реестр обновлений ЕРП» (последнее изменение 19.10.2026). Это источники документации, а не наблюдение текущих настроек школы.

Подтверждено документацией:

- Задачи привязываются к посетителю, лиду или создаются без клиента; при превращении лида в посетителя задача сохраняется.
- У задачи есть номер, название, срок, ответственные, комментарий, дата выполнения и посетитель; возможны несколько исполнителей. Есть фильтры территории/филиала, даты и выполненных задач.
- В обновлении 19.03.2026 явно убрано время из задач: создание, дедлайны, фильтры и сортировка ограничены датой. Текущий клиентский интерфейс CRM без времени соответствует этому правилу.
- Реестр описывает отдельный архив задач и выборочную/массовую архивацию. Архив не равен доказательству фактического выполнения.
- В старом описании виджета указаны «Просроченные», «На сегодня», «Мои задачи», «Все задачи» и окно дат месяц до/после текущей даты. Нынешние настройки и фильтры вашей школы требуют отдельной проверки.
- Инструкция 2022 ещё не описывает готовые автоматические цепочки: на тот момент автоматизация только планировалась. Из неё нельзя выводить интервалы недозвонов, обработку ПУ, оплаты или продления в ноябре 2026.

Обнаруженные зоны риска в коде CRM: собственная лесенка повторных звонков, автоматическая генерация задач из этапов и отметок ПУ, снятие автоматических задач при смене этапа, отдельный процесс повторного приглашения на ПУ. Сходные комментарии «как в ERP» не являются доказательством равенства актуальным настройкам ERP. В этом блоке эти цепочки не переписывались без источника.

Ранее Юлия отдельно задала общие клиентские задачи для всех администраторов, без выбора исполнителя, приоритет внутри даты и проверку продления на 20-е последнего месяца. Эти явные решения не отменялись только по старой инструкции 2022 о личных исполнителях. Личные задачи сотрудников отделены от клиентского переноса.

## Новый путь переноса

Настройки → Перенос из ERP → «Перенести клиентские задачи ERP».

1. Загрузить CSV/XLSX реестра задач (можно несколько файлов). Даты не ограничены 9–15 ноября: поддержаны прошлые, текущие, будущие, выполненные и явно архивные записи.
2. Нажать «Проверить перенос». Чтение и расчёт не изменяют задачи. Сопоставление только по отдельным ID задачи и клиента ERP, с учётом пространства ID посетителей/лидов; имена не используются как доказательство связи.
3. Просмотреть добавления, изменения по ID, совпадения, повторные строки, даты, состояния и исключения. История событий, неизвестные состояния, потерянные связи клиентов, автоматические дубли и неоднозначные старые задачи выводятся для разбора.
4. «Перенести проверенные задачи» создаёт резервную копию и применяет только проверенный план. Если после проверки изменились файлы, задачи или связи ID, план отклоняется. Оплаты, абонементы, посещения и этапы клиентов не затрагиваются.
5. После применения каждая принятая задача повторно сверяется по клиенту, названию, дате, состоянию и комментарию. Результат и все исходные колонки сохраняются в приватной базе. Отчёт можно скачать. При исключениях интерфейс явно называет перенос частичным.

Повторная загрузка по тому же ID не создаёт вторую задачу. Ранее импортированные ERP-задачи, отсутствующие в выбранных файлах, перечисляются отдельно и автоматически не закрываются: отсутствие в отфильтрованной выгрузке не доказывает удаление. Ручные поручения CRM не подменяются.

Путь принимает реестр с явным состоянием (открыта/выполнена/архив). Автоматическое распознавание актуальной выгрузки именно вашей ERP пока не подтверждено: после чтения живой системы может понадобиться уточнить заголовки и значения состояния. Несколько исполнителей, автор и исходное состояние сохраняются как поля источника в отчёте; клиентские задачи доступны всем администраторам по ранее заданному правилу.

## Следующие шаги после входа

- Прочитать текущий реестр и настройки генерации/переходов; проверить задачи на сегодня, просроченные, будущие, выполненные и архив.
- Установить точный формат выгрузки, сохраняющий ID задач и ID клиентов; проверить полноту относительно фильтров ERP.
- Сверить существующие привязки, автоматические дубли и изменения другого Work-чата; не запускать конкурирующие импорты.
- Выполнить предварительную сверку всех выгруженных задач, разобрать исключения, затем применить проверенный пакет и дать итог по датам/статусам. Перенос не называть полным при оставшихся исключениях или невыгруженных разделах.
