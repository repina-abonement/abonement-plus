# CRM-179 — архив клиентских данных и чистый старт

## Решение владельца

Нынешние клиентские данные нужно целиком сохранить вне рабочего контура, после чего начать заполнение CRM заново небольшими подтверждёнными этапами. До 02.11.2026 источником будет ERP, сведения после этой даты сохранены отдельно вручную. Правила абонементов, тарифы, филиалы, группы, расписание, команда и настройки должны остаться.

## Подготовленный безопасный механизм

В «Настройки → Перенос из ERP → Начать CRM с чистого листа» руководитель сначала получает план с количеством строк по каждому виду. Применение доступно только после ввода точной фразы подтверждения.

До изменения рабочих данных сервер обязан:

1. проверить, что подключено внешнее зашифрованное резервирование;
2. создать отдельный полный SQLite-архив текущей базы;
3. выполнить `quick_check`, сравнить количество строк и SHA-256;
4. загрузить зашифрованную копию во внешнее хранилище;
5. повторно проверить, что после плана и во время архивации клиентские данные не изменились.

Если любой шаг не подтверждён, очистка не начинается. После успешного архива единая транзакция убирает из рабочей CRM карточки семей и детей, занятия, посещения, продажи, оплаты, возвраты, ссылки, чеки, банковские/фискальные сверки, переписки, звонки, клиентские задачи и прежние сырые выгрузки ERP. Проверка внешних ключей выполняется до фиксации.

Сохраняются правила и тарифы, филиалы и группы, расписание, команда и роли, настройки и подключения, общие задачи и расходы. Полный старый аудит остаётся в архиве, а в чистой CRM не влияет на новые расчёты.

В рабочей базе остаётся реестр архива: время, имя локального файла, имя зашифрованной внешней копии, SHA-256, количество строк до/после и версия кода. Возврат старой базы выполняется только отдельной операцией обслуживания: автоматического отката поверх новых данных нет, чтобы не потерять сведения, внесённые после чистого старта.

## Проверки

- успешный архив и очистка на отдельной SQLite-базе;
- структурные данные и общая задача сохраняются, клиентская задача удаляется;
- полный архив действительно содержит исходную карточку;
- изменение данных после плана блокирует применение до создания копии;
- отсутствие внешнего резервирования блокирует план;
- сбой внешней загрузки не меняет рабочую базу;
- проверки CRM-177 и защищённого восстановления Мамедова продолжают проходить;
- интерфейс восстановления Мамедова: 69 браузерных утверждений без рабочего применения.

**Опубликовано:** `5d8082645c3a74153c39eb2973c9a4eb83fa2ba8`; рабочий API подтвердил версию 20.11.2026 в 17:28 МСК. Фактическая очистка ещё не запускалась: требуется авторизованный план руководителя, затем явное подтверждение в форме. До применения новые платежи, возвраты, чеки, банковские команды и сообщения не создавались.

После первой публикации владелец не увидел блок: он ошибочно создавался только внутри интерфейса уже завершённого старого переноса ERP. Исправлено размещение непосредственно в корне раздела «Перенос из ERP», независимо от состояния прежнего импорта. Публикация этой правки и повторная проверка видимости отмечаются отдельно.

При первом рабочем применении браузер получил HTTP 504 во время создания/загрузки копий. Это не доказывает ни успех, ни отмену: сервер мог завершить операцию после тайм-аута прокси. Повторный запуск до проверки запрещён. Добавлен отдельный читающий статус и кнопка «Проверить результат»: они показывают зарегистрированный архив, SHA-256 и точное число оставшихся клиентских строк. После сетевой ошибки форма больше не предлагает сразу новый план.

Рабочая проверка статуса показала: завершённого архива в реестре нет, в CRM осталось 219 158 клиентских строк; очистка не произошла. Длительную операцию переработали в фоновую серверную задачу. HTTP-кнопка теперь только запускает её и сразу возвращает номер, а страница опрашивает состояния «локальный архив → внешняя копия → очистка → готово». На время внешней загрузки сервер удерживает блокировку записи после проверки локального снимка: новые строки не могут попасть под очистку, не войдя в архив. Перезапуск отмечает незавершённую задачу как прерванную; повтор вслепую запрещён.

Первый запуск фоновой версии вернул общий HTTP 500 до создания задачи; статус показал 219 162 строки и отсутствие очистки. Точную причину старый ответ не сохранил. Добавлены увеличенное ожидание SQLite при регистрации задачи, понятная ошибка временной блокировки и безопасная диагностика типа/строк запуска в читающем статусе без значений запроса, секретов и клиентских данных. До публикации этой защиты повтор запрещён.
