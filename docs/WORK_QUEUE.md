# Единая очередь CRM «Абонемент Плюс»

Актуализация: 13 ноября 2026, Москва. Это основной поддерживаемый список задач из Claude и доступной переписки с Юлией. Новые требования, решения, проверки и блокеры добавлять сюда после каждого блока работы без отдельного напоминания. Реестр договорённостей — `PROJECT_REGISTER.md`.

Статусы: **осталось** — результата нет; **код** — реализация и локальная проверка есть, рабочий результат отдельно не подтверждён; **проверка** — требуется проверка подключения/настройки/данных; **заблокировано** — указан конкретный блокер; **вопрос** — решение ещё не принято. Наличие модуля не означает завершение задачи. Выполненные пункты не удалять: сохранять результат и доказательство. Последнее явное решение Юлии важнее старой формулировки Claude.

Завершение — только после денег и успешного фискального чека. Прямой автоматический запуск возврата из CRM не реализован. До действия — согласование с Юлией, в форме только дата согласования. |

## Детали ранее обсуждённых интерфейсных требований

- Навигация: различимые разделы/подразделы, сворачиваемые группы; история поиска/недавно открытых клиентов. Сверить актуальный интерфейс с исходными замечаниями, не считать удобство закрытым без проверки.
- Переписка: заметная дата дня при прокрутке, смайлы и собственные стикеры; большое поле ввода; существующая переписка семьи подтягивается по однозначной связи. Код и рабочая доставка — разные проверки.
- Продажа: группа и тариф предлагаются по прошлому абонементу и доступны для изменения; месячный/разовый выбор; единая кнопка продажи, без дублирующих кнопок и «только выставить счёт».
- Календарь продажи: отмеченные занятия и ручные исключения дат; убрать дублирующую строку дат; перерасчёт гибкого тарифа только по запросу клиента, при соблюдении правил предыдущего месяца.
- Текст оплаты: без приветствия, с абзацами, без дней недели в названии «Сборная Арктика». У сборной нет жёсткого возрастного порога; допуск определяет тренер.
- Перевод рядом с действующим абонементом: остатки Арктики и ОФП вместе идут в новую группу; разница — доплата или баланс. Историю платежей/посещений сохранять.
- Карточка: возраст в годах и месяцах, компактные контакты без визуального разрыва, сохранение открытой карточки/вкладки при обновлении, читаемые абонементы/платежи, удаление лишнего блока групп.
- Посещения: полноценные подписи в ячейках, крупная область отметки; различать абонемент/отработку/ПУ; показывать пропуски и доступные отработки, предлагать менее заполненные подходящие группы, готовить редактируемый текст без самовольной отправки.
- Первый вход: кнопка выхода доступна до подписания; лишнюю фразу о запросе копии документов убрать. Юридическую силу подписи отдельно не обещать.

## Как поддерживать список

- После обсуждения добавлять требование/решение с источником и датой; после изменения — проверку, ограничение и следующий шаг. Сохранять историю уточнений, не удалять невнедрённое ради чистоты списка.
