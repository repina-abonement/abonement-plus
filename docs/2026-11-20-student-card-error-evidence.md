# CRM-177 — получение фактической ошибки чтения карточки

По сообщению владельца, GET `/api/students/1719` под руководителем вернул 500 «Ошибка сервера». До него успешно рассчитан план восстановления на полной копии, но применение не нажимали. **Рабочее восстановление не выполнять.** Сначала, по уточнению Юлии, опубликован CRM-176; диагностика ошибки подключается после него.

Из этого окружения нет прямого доступа к рабочему Python-журналу или авторизованной карточке. Существующий `/api/diag/conn` читает nginx-соединения, а не Python traceback. Финансовая реконструкция на 38 денежных строках / 36 покупках с синтетическими дополнительными связями успешно читает `student_detail`; реальные связи семьи, групп, посещений, истории и кэшей не предоставлены. **Точная причина рабочего сбоя ещё не установлена.**

Подготовлен ограниченный сбор метаданных фактического исключения в обработчике HTTP 500: только GET `/api/students/<id>`, случайный `error_id`, тип, безопасное сообщение, относительные файлы CRM, номера строк и функции настоящего traceback. Request/body/query/куки/локальные переменные/значения и исходные строки кода не сохраняются. Кольцо ограничено памятью процесса, очищается после рестарта, в БД и файлы не пишет. Сбой самого сбора не маскирует прежний ответ 500. Вебхуки, банковские callback и другие методы не захватываются.

Только руководителю доступен читающий GET `/api/diagnostics/student-card?student_id=1719`, при необходимости с `error_id`. Он возвращает только фактические сохранённые события; отсутствие события не превращается в гипотезу причины. Чтобы получить сведения после публикации: один раз повторить открытие проблемной карточки, затем прочитать этот адрес. Это получение доказательств, не исправление неизвестной причины.

17 проверок прошли, включая HTTP: реальное исключение временного обработчика, откат транзакции при 500, запрет диагностики другим ролям, отсутствие денежных изменений при успешном чтении и диагностике, отсутствие приватных значений, отказ захватывать другие методы/ошибки 400, безопасный отказ сбора. При тестах рабочие данные и провайдеры не использовались. Публикация и фактический ответ Work фиксируются отдельно.
