# Оплаченная неделя и срок отработки

## Последнее решение

Юлия: пропуск отрабатывается в том же месяце или следующем подряд; месяц отработки оплачен месячным абонементом. В неделе пн–вс минимум две оплаченные тренировки по абонементу, отработка дополнительная третья/четвёртая/далее. На уточняющий вопрос Юлия ответила: достаточно двух оплаченных по расписанию, ждать посещения не нужно. Другие виды занятий этот минимум не заменяют.

## Реализация

makeuppolicy.check проверяет оплату целевого месяца и точные оплаченные занятия недели по календарю, снимкам состава, исключённым датам и срокам абонемента. Неделя на границе месяцев читает оба месяца с их оплатой. Общая оплата/баланс не подменяют месячный абонемент, разовые/пробные/отработки не создают минимум. Окно пропуска определяется по дате будущей отработки, а не по дате оформления записи. Подбор и book_makeup используют один модуль; API повторно проверяет актуальные данные. Подбор возвращает разрешённые ID пропусков для каждой даты, интерфейс отключает кнопку для выбранного пропуска, если его срок не подходит. Правило показано в карточке. Ограничения сборной, вместимости и текущих групп сохранены.

Существующие отметки, платежи и брони автоматически не переписываются. Отработки ERP без исходной связи с пропуском — отдельный CRM-052, их нельзя вычитать произвольным сопоставлением.

## Проверки

Пройдены test_makeup_policy, test_client_attendance, test_crm, test_capacity, test_subcomposition, test_journal_month и Python/JS syntax. Проверены неоплаченный месяц, один вместо двух оплаченных дней, точный снимок, третье и четвёртое занятие, истечение октябрьского пропуска к декабрю, неделя на границе года, отмена брони/возврат резерва, согласованность подбора с API. Старые fixtures test_crm/test_capacity/test_client_attendance обновлены: нужные для отработки два занятия и оплата теперь заданы явно. Реальные данные/сообщения клиентам не затронуты; опубликованный файл проверяется отдельно.
