# Абонемент Плюс: памятка для того, кто продолжит работу

Состояние на 30.10.2026. Всё, что касается договорённостей с владельцем, правил школы и
списка дел, лежит в закрытом документе владельца «Абонемент Плюс: всё о CRM на 30.10.2026»
(Claude Docs, ссылку даёт владелец). Здесь только то, что нужно для работы с кодом.

## Как работать

- Ветка `main`. Перед каждым push: `git pull --rebase origin main`, потом `git push origin main`.
  Сервер (Timeweb, https://185-207-65-245.sslip.io) сам подтягивает `main` примерно раз в 5 минут
  (`deploy/update.sh`), поэтому всё запушенное сразу уходит в работу.
- Перед push прогнать все тесты: `for f in tests/test_*.py; do python3 -m tests.$(basename $f .py) || echo FAIL $f; done`.
- Порядок с владельцем: предложить, спросить, делать после «да». Объяснять простыми словами, без терминов.
- Тексты в интерфейсе без длинного тире, подписи должностей с заглавной, лишней информации на экране нет.
  Тренерам: крупные кнопки, телефон, юмор.
- Настоящих клиентов в базу не заводить, пока не поданы изменения в Роскомнадзор и не опубликована
  политика ПДн. Скриншоты для посторонних только с тестовой копии. Данные с рабочего сайта
  не копировать и не удалять без разрешения владельца. Входа на рабочий сайт у помощника нет.
- Адрес `/hooks/lead/<секрет>` секретный: не коммитить и не выкладывать.
- Репозиторий публичный: никаких ключей, паролей, клиентских данных, договоров и сумм аренды в коде.

## Устройство

- Python 3.11+, только стандартная библиотека. SQLite в режиме autocommit, транзакции `BEGIN/COMMIT`
  в обработчике запроса.
- `crm/server.py`: HTTP-сервер, маршруты `@route(method, pattern, role=...)`. `role` это строка прав:
  `"all"`, старые `"admin|operator|any|coach"` или `"раздел[:own|view|full]"`, варианты через `|`.
  Проверка в `perms.allowed`.
- `crm/perms.py`: таблица прав `SECTIONS` (раздел → должность → full/view/own). Должности:
  руководитель (`admin`), старший администратор (`is_senior`), администратор (`operator`), тренер (`coach`),
  юрист (`lawyer`), отметка промоутера (`is_promoter`, права складываются). Выгрузка `export` только у руководителя.
- Миграции: в `init()` каждого модуля через `PRAGMA table_info` и `ALTER TABLE`, все вызываются из `db.init_db`.
- Фоновый цикл `tasks.run`: `pu.tick`, `coachreport.tick`, `schedule.apply_versions`, напоминания, чеки.
- Интерфейс: обычный JavaScript в `crm/static/*.js`, подключается в `index.html`. Помощники `can(sec, lvl)`,
  `isOwner()`, права в `S.meta.user.perms`.
- Сообщения в рабочие чаты: `pu.notify_chat(con, "care"|"coaches", text)`. Работают только после
  подключения Telegram-бота через сервер-посредник (`deploy/relay`).

## Ключевые модули

| Модуль | Что делает |
|---|---|
| `services.py` | ученики, абонементы (`quote_for`), журнал, карточка (`student_detail`), отмена абонемента |
| `money.py` | оплаты, `reconcile` (раскладка по абонементам от старых к новым), `balance`, оплата за семью, перенос, возврат, лента |
| `pricing.py` | прайс с датой, +5% и без скидок после 25 числа (с `LATE_FROM = "2026-12"`), «Корректировка», новичок |
| `schedule.py` | расписание, версии группы «с даты» (`group_versions`, `on(con, g, d)`) |
| `transfer.py` | перевод в другую группу с абонементом |
| `coachreport.py` + `static/report.js` | отчёт тренера о смене, напоминания 30 минут и 2 часа, задачи по итогам пробных |
| `mypay.py`, `salary.py` | «Моя зарплата», цели, расчёт зарплат |
| `pu.py` | пробные, воронка, окна «пригласим позже» 1-15 августа и 5-10 января |
| `comms.py` | чаты, звонки, заявки с сайта (`lead_fields`, настройка `lead_notify`) |
| `merch.py` | мерч и пересчёт склада |
| `backup.py` | ночные копии, шифрование, Яндекс Диск, фото (`upload_photos`) |
| `fiscal.py` | сверка чеков 54-ФЗ |
| `analytics.py` | дашборд, отчёт «Пробные» |

## Настройки, которые важно знать

- `coach_reports_from`: с какой даты ждём отчёты тренеров (раньше не считаются несданными).
- `cert_required_from = 2026-12`: с этого месяца перерасчёт на «Гибком» только по пропускам с медсправкой.
- `lead_notify`: CRM сама пишет о заявке в «Службу заботы». Включать после бота, затем выключить Google-скрипт.
- `CRM_DEMO=1` на сервере: выдуманные клиенты подсыпаются, только пока в базе нет настоящей команды;
  сотрудники с «тест» в имени уходят в архив, когда настоящая команда есть.

## Проверка вживую на тестовой копии

```
CRM_DB=/tmp/x.sqlite3 CRM_ADMIN_PASSWORD=demo-pass-123 CRM_DEMO=1 CRM_QUIET=1 CRM_PORT=8765 python3 -m crm.server
```

Вход `admin` / `demo-pass-123`. Остановить: `pkill -f "python3 -m crm[.]server"`.
