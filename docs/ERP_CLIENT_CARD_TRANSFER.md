# Поэтапный перенос карточек клиентов из ERP

## Массовый перенос посетителей, 26–27.11.2026

1. В «Настройки → Перенос из ERP → Карточки клиентов, статусы и лиды» выберите «Посетители (39).xlsx» и «Посетители (40).xlsx». Оставьте «Лиды» и «Только указанные ERP ID» пустыми. Включите создание отсутствующих карточек и дополнение пустых полей, затем нажмите «Проверить».
2. Сверьте, что выбрано 2 606 строк посетителей и 0 лидов. При повторном запуске для двух филиалов проверьте число новых карточек и дополняемых полей перед нажатием «Перенести». Первый запуск создал 2 172 карточки и обработал 129 существующих.
3. Заполненные поля CRM имеют приоритет. Если филиал CRM пуст и ERP указывает два, оба сохраняются в «Филиалы из ERP». Заполненный филиал CRM сохраняется. В первичном отчёте было 36 таких замечаний.
4. По Максиму Мастеренко перенос подтверждён владельцем. Строки с неоднозначной личностью сверяются отдельно. В выборке из 210 строк с разными телефонами 63 относятся к совпадающим имени и фамилии, 133 к одному слову и 14 к двухсловным заглушкам.
5. Согласованное правило для остатка: совпадение фамилии ребёнка и полного телефона родителя достаточно при единственной подходящей карточке CRM. Автоматическое сопоставление по этому правилу пока не реализовано. Предпросмотр действующей версии его не использует.
6. Перенесённые карточки исключены из «Свежих новых карточек». Для ожидания задач и абонементов добавлена воронка «Карточки из ERP» с задачей без срока, вне счётчика «Сегодня». Эти изменения опубликованы. Применение к рабочей выдаче после входа требует проверки.

## Первый этап

Сначала переносятся клиенты, которые занимались в октябре 2026 года. Этот этап не читает и не создаёт счета, оплаты, возвраты, чеки и свободный баланс. Денежный учёт начинается в CRM отдельно с чистого состояния.

Карточки детей из сборной уже внесены вручную. Их нельзя создавать повторно. Сопоставление выполняется в таком порядке:

1. сохранённая связь с ID ERP;
2. точный ID ERP в карточке;
3. однозначное совпадение нормализованного телефона родителя и имени ребёнка;
4. неоднозначное совпадение не применяется и выводится на сверку.

## Обязательные поля проверки

Из строки клиента читаются и показываются в предварительном плане:

- имя и фамилия ребёнка;
- дата рождения ребёнка;
- телефон родителя;
- имя родителя;
- роль родителя;
- электронная почта;
- рекламный источник;
- комментарий.

Если значение есть в ERP, а поле CRM пустое, оно будет дополнено. Если оба значения заполнены и расходятся, CRM сохраняет текущее значение и показывает обе версии для ручной сверки. Отсутствующее значение не придумывается. Комментарий добавляется в историю карточки один раз; повторный перенос не создаёт его повторно.

## Порядок безопасного запуска

1. Загрузить выгрузки посетителей и лидов в «Настройки → Перенос из ERP».
2. Открыть «Карточки клиентов, статусы и лиды», выбрать файлы и нажать «Проверить».
3. Сверить количество новых и совпавших карточек, список дополняемых полей, пропуски источника и расхождения.
4. Отдельно убедиться, что дети из сборной находятся как существующие карточки и не входят в число новых.
5. Сначала применить этап на копии рабочей базы и проверить несколько карточек каждого типа: существующая сборная, обычный октябрьский клиент, общий родитель у двух детей, отсутствующее поле, конфликт CRM/ERP.
6. Только после этой проверки применять тот же подтверждённый план к рабочей базе.

Повторный запуск с теми же файлами обязан сохранять одну карточку, одного родителя, одну связь ID ERP и один комментарий. Он не должен создавать финансовые записи.
