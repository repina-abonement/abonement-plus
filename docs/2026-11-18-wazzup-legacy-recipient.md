## Подтверждение и границы

Поддержка Wazzup сообщила: в части примеров номер телефона был передан в chatId; исправленный запрос через phone сработал. Другой корректный запрос вернул Cannot found contact by phone: контакта действительно нет в MAX. Ответ не позволяет связать эту причину с исходным WhatsApp requestId 303f01b4fb5fc6d7c84b568d8b7862ee. Полный исходный запрос в доступных локальных файлах не найден, рабочие логи недоступны. Восстановленный пример не выдаётся за фактический запрос

После этапа только чтения Юлия разрешила исправление словами «сделай так, чтобы всё корректно работало». Рабочие сообщения для проверки не отправлялись

## Изменения

- Новые phone:/username:-переписки сохраняют прежнюю корректную адресацию
- Старые TG/MAX-переписки с external_id, совпадающим с сохранённым телефоном, используют phone при отсутствии подтверждённого входящего сообщения. По одной длине цифр телефон не определяется
- resolvedChatId из ACK/webhook имеет приоритет. Настоящий числовой ID сохраняется, включая случай совпадения с телефоном при доказанном входящем сообщении
- Общая функция используется для текста, стикеров и файлов с подписью
- ACK сохраняет реальный chatId и для старой записи; следующая отправка использует подтверждённый ID
- Входящие Telegram/MAX вебхуки сохраняют подтверждение реального ID
- WhatsApp сохраняет формат chatId с телефонным идентификатором, автоматической замены на phone нет
- Cannot found contact by phone получает понятное пояснение; исходный код/описание/requestId сохраняются. Автоповторов и перехода в другой мессенджер нет
- Диагностика показывает фактически выбранный режим адресации старой записи; понятная подпись в интерфейсе, машинный режим в копируемом отчёте
