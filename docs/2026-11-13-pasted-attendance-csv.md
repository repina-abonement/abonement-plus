# CSV посещений текстом: список и предварительная сверка

Поручение Юлии: Настройки → Перенос из ERP → Полная сверка и сохранение исходных данных; поле «Вставить CSV посещений», кнопка «Добавить CSV посещений», upload с явным kind=visits. Это обход ограничения передачи локального файла браузерной автоматизацией, а не новый способ немедленного импорта.

Основная форма уже присутствовала из 24a0494 (cherry-pick f26996e). Уточнено отображение: каждый файл в полной сверке показывает kind_label («Посещения»), после загрузки раздел обновляется и сообщает следующий шаг. Исходный текст CSV передаётся в UTF-8 без trim исходных данных (trim используется только для проверки пустоты). При ошибке текст сохраняется, причина показывается внутри раскрытого блока. Обычная файловая загрузка и существующие admin-права API не менялись.

Перенос остаётся ручным: выбрать файл → «Проверить выбранные файлы» → после проверки «Сохранить и перенести проверенное». Загрузка не запускает apply автоматически.

Проверки: 25 tests.test_erpfull; новый тест проходит существующий server.erp_upload с base64 и visits. Заголовок «Задача (end)» специально заставляет автоопределение выбрать tasks, но явный тип даёт visits/«Посещения». Последующая full.plan даёт одно предлагаемое посещение и токен; рабочая тестовая БД не меняется, attendance/tasks остаются пустыми. Chromium 390/1440: пустой ввод, ошибка/сохранность текста с переводами строк, явный visits, UTF-8, обновлённый список и подпись, предварительный план, apply не вызван. Синтаксис JS и diff проверены.

На рабочую CRM CSV с клиентами не загружался, импорт не применялся, сообщения и оплаты не менялись. Проверка доставки публичного JS выполняется отдельно; без авторизованного входа рабочая загрузка/preview не объявляются проверенными.
